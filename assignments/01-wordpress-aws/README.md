# Assignment 1: Deploy WordPress Using Terraform

## Project objective

This project uses Terraform to deploy a complete WordPress lab stack on one AWS EC2 instance. The instance bootstraps itself with Apache, PHP, MariaDB and WordPress through an automated user-data script.

## Architecture

```text
Internet
   |
   | HTTP :80
   v
AWS security group
   |
   v
Ubuntu EC2 instance
   |-- Apache
   |-- PHP
   |-- WordPress
   `-- MariaDB
```

This single-instance architecture is suitable for a learning assignment. A production design would normally separate the database, use private subnets, HTTPS, backups, load balancing and stronger secret management.

## Files

| File | Purpose |
|---|---|
| `versions.tf` | Terraform and provider requirements |
| `providers.tf` | AWS provider and default tags |
| `main.tf` | AMI lookup, security group, password and EC2 instance |
| `variables.tf` | Typed and validated input variables |
| `outputs.tf` | Instance details and public endpoint |
| `wordpress-user-data.sh.tftpl` | Installs and configures the full WordPress stack |
| `terraform.tfvars.example` | Safe example input values |

## Prerequisites

- Terraform installed
- AWS CLI configured or another supported AWS authentication method
- An AWS account with permission to manage EC2 and security groups
- A public subnet that assigns public IP addresses, or use the default VPC

Check authentication:

```bash
aws sts get-caller-identity
```

## Deployment

```bash
cp terraform.tfvars.example terraform.tfvars
terraform fmt -recursive
terraform init
terraform validate
terraform plan -out=tfplan
terraform apply tfplan
```

Display the website URL:

```bash
terraform output wordpress_url
```

Cloud-init and package installation may take several minutes after Terraform finishes. Open the URL when the bootstrap process has completed.

## Verification

The browser should display the WordPress installation page. On the instance, useful checks include:

```bash
sudo cloud-init status --wait
sudo systemctl status apache2
sudo systemctl status mariadb
sudo tail -n 100 /var/log/cloud-init-output.log
test -f /var/lib/wordpress-bootstrap-complete && echo complete
```

## Troubleshooting

### The URL does not load

- Wait for `cloud-init status --wait` to complete.
- Confirm the EC2 instance has a public IPv4 address.
- Confirm TCP port 80 is allowed by the security group.
- Check `/var/log/cloud-init-output.log`.
- Confirm Apache is active.

### WordPress shows a database error

- Confirm MariaDB is active.
- Review the bootstrap log without publishing credentials.
- Confirm `wp-config.php` exists and is readable by the web server.

### Terraform proposes unexpected replacement

Read the plan carefully. Changes to immutable EC2 arguments or user data may replace the instance depending on provider settings.

## Security decisions

- HTTP is open publicly because the assignment requires a public endpoint.
- SSH is disabled unless `admin_cidr` is explicitly supplied.
- Database credentials are generated by Terraform rather than hardcoded.
- The password is still present in Terraform state and user data, so state must be protected.
- No AWS credentials or private keys belong in this repository.
